## Questions

### Q1 — 既存リポジトリの導入完了に、どの証拠までを必須にするか

- **背景 / 具体例**: 架空の会員プロフィール更新には `make test` が無く、PHPUnit の単体テストはある。その単体テストが緑でも、プロフィール更新の HTTP から DB までを固定するテストは無い。別コンテキストの事実照合は文書の読みを見るだけで、コードは動かない。
- **なぜ人間の判断が要るか**: どこまでを導入完了と呼ぶかは、既存製品に払う作業の範囲であり、品質の約束になる。
- **A: 00 まで** — カルテ、別コンテキストの事実照合、実在する lint とテストランナーの実行。ケースの漏れと SIT の不在は「未実装」と書く。00a と 00b は任意。
- **B: 00 と 00a** — A に加え、既存ケースが契約の分岐を漏れていないか、アサーションが現行の挙動と合っているかを確認する。新しい SIT を書く 00b は任意。永続化や境界をまたぐ行に SIT が無いことは、完了報告に残る。
- **C: 00 と 00a と 00b** — 永続化または境界をまたぐ Flow は、既存ランナー上の SIT を足して実行するまで導入完了にしない。SIT の責務が無い Flow は 00b を外してよい。
- **推奨: B**。実行テストを事実照合で代用しない、という対話と一致する。同時に、業務リポジトリへテストのコミットを必ず作らない。SIT が主であることは、穴として残し、足すかどうかは 00b の選択に残る。
- **回答が無いと止まるもの**: 00 以外のプロンプト文面。

### Q2 — 既存ケースの監査は、00 に含めるか、00a として分けるか

（Q1 で B または C）

- **背景 / 具体例**: 架空の Pack は、既存の単体テストと、未実装の `SYS` 行を分けて書ける。アサーションが保存の失敗や境界を見ていない、という判断は別の作業である。
- **なぜ人間の判断が要るか**: 同じ導入の中でカルテと監査を終えるか、監査前で止まれるかを決めると、00 だけの完了が何を意味するかが変わる。
- **A: 00 に含める** — カルテと同時に監査する。00 が終わった時点で、既存ケースの漏れと正しさも見ている。工程は増えないが、00 の一回が重くなる。
- **B: 00a に分ける** — 00 はカルテ、事実照合、実在コマンドの実行で止まれる。00a が終わっていないことは、監査前と分かる。00b は 00a のあとにだけ始める。
- **推奨: B**。対話で出た三段と一致する。00 だけで止めた導入を、SIT 監査済みと読まないため。
- **回答が無いと止まるもの**: 監査の節をどのプロンプトに書くか。

### Q3 — 必須と書くのは、既存リポジトリで一度実行してからにしますか

- **背景 / 具体例**: 00 の事実照合は、対話のあとプロンプトへすでに書いた。00a は、このリポジトリの記録としてはまだ実行していない。対話では、代替の品質担保を実現したあとで各工程を MUST にするとした。
- **なぜ人間の判断が要るか**: 未試行の工程を完了の必須にすると、次の導入がプロンプトに従って止まる。試行後にすると、それまでの導入は手順があっても必須完了ではない。
- **A: 回答の直後に、選んだ段をプロンプトの必須として書く** — 次の導入から揃う。00a の一回目は、その必須の初回になる。
- **B: 手順は回答後に書くが、必須の完了条件にするのは、既存リポジトリでその段を一回実行してから** — 初回は試行である。試行の結果を見てから MUST にする。それまでは、書いてあっても未実施を完了扱いにできる。
- **推奨: B**。00a は未試行（U1）である。事実照合を 00 に先に書いたのは、文書の読みと実行テストが別だと分かったからである。00a には、その実行記録がまだ無い。
- **回答が無いと止まるもの**: プロンプトの文言を「必須」と書くタイミング。

### Q4 — 00 の完了を、資料と既存ランナーの実行に分けるか

- **背景 / 具体例**: 架空の会員プロフィール更新には PHPUnit がある。カルテと事実照合は、そのテストを起動できない環境でも閉じられる。Q1 は、その実行を 00 の完了に含めている。ランナーがリポジトリにあるのに起動できないと、資料が揃っていても 00 は終わらない。
- **なぜこの記録があるか**: Q1 と Q2 は、既存ランナーの実行を 00 の完了に含めて受諾している。2026-10-29 の対話で、人間はその実行を 00 の完了から外し、プロンプトファイルも分けると答えた。未決の質問ではなく、受諾の置き換えである。
- **A: 00 の完了に実行を残す** — 今の Q1 のまま。資料の照合が終わっても、既存ランナーの結果が無い 00 は完了ではない。
- **B: 完了を分ける** — 00 は資料、既存テストの所在、実在するコマンドの文面、独立した事実照合で止まる。ランナーを起動し、緑・赤・起動できなかった理由を残すのは、隣のプロンプトの完了である。00a と 00b は今どおり 00 の外である。00 の完了を SIT 検証済みとは呼ばない。
- **推奨: B**。事実照合は実行の代わりにならない、という Q1 の理由は残る。起動できない環境が、資料の完了を止めない。
- **回答が無いと止まっていたもの**: 00 の完了条件から既存ランナーの実行を外すこと。プロンプトファイルを分けること。2026-10-29 の回答で止まっていない。
- **回答**: B。この対話、2026-10-29。プロンプトファイル自体を分ける。ファイル名は AI 技術判断。
